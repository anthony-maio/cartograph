# Hermes plugin verification

The native Hermes integration passed against a packed Cartograph installation on 2026-10-28. The package was built locally from the changes in this delivery; npm 1.2.2 remains the previously published release.

## Real repository acceptance

The task was: `Validate unknown LLM providers and require API keys in the CLI`.

Before the context changes, the real Hermes loader and dispatcher ran the tool successfully, but the returned context omitted `src/cli.ts`. After the changes, the default six-file result included `src/cli.ts` lines 330-409, containing both the unknown-provider guard and the API-key requirement, plus `tests/cli/llm-mode.test.ts`. Every returned source excerpt and line range was checked against the working repository. This is a concrete regression check, not a general retrieval-quality benchmark.

The acceptance script used the actual Cartograph installer and an isolated Hermes profile. It verified unchanged host configuration, packaged asset hashes, runtime bindings, both installation doctors, native plugin discovery, model-facing tool definitions, both tool dispatches, useful source context, invalid-directory errors, profile cache placement, and removal of tools on unload. All 17 checks passed. The script invokes the real dispatcher directly; it does not establish autonomous model tool selection.

The same package was installed and enabled in the normal WSL profile, and its installation doctor passed. A subsequent model-driven chat check was blocked before inference by the existing Hermes gateway state, `Gateway draining: update_paused`; the response reported zero input and output tokens. Native tool verification passed, but a normal model-driven session remains unverified until that host update is recovered. No gateway, unrelated process, or install lock was removed to bypass the state.

## Reproduce

Run the normal package checks, then follow [the Hermes setup guide](../examples/hermes.md). In the same OS environment as Hermes:

```sh
python3 scripts/hermes-smoke.py \
  --hermes hermes \
  --hermes-source /path/to/hermes-agent \
  --profile-parent /path/to/hermes-home/profiles \
  --cli /path/to/installed/cartograph/dist/cli.cjs \
  --plugin /path/to/installed/cartograph/assets/hermes \
  --repo /path/to/cartograph-checkout \
  --output /tmp/cartograph-hermes-verification.json
```

The source checkout is the real acceptance target. The CLI and plugin arguments must refer to the same installed package. The script disables lazy dependency installation and removes its temporary profile after the check.
